How the monster got built

Nobody planned this. It accumulated.

2014

A PHP monolith

The founder's cousin built it. It worked, mostly, and nobody wrote anything down.

2019

Half a rewrite

A new team ported the backend to Python on half a budget. Payments and PDFs stayed behind in the old PHP service.

2021

Go and Redis, bolted on

To survive a big on-sale, someone wired a Go service straight into the old PHP, around the new API. That team is gone too.

2023

A new face

A contractor rewrote the frontend in Next.js, then left mid-project.

Nobody has the full picture.
Now it's your turn.

Fix it on paper

The main branch only gets worse. Your fix is an answer, not a patch.

Pick

Choose an issue. Each one documents exactly one flaw, tagged by discipline and difficulty.

Fork

Work in your own fork on a solution branch. Nothing you do touches the monster.

Fix

Open a pull request. It will never be merged, and that is the point. It is your answer, on the record.

Vote

The community reacts with a thumbs-up. The top-voted pull request is the crowd's best answer.
